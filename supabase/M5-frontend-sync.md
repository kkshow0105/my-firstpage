# 双表记账 M5 前端同步

## 日常操作

在菜单或页面上方的状态按钮打开「云端账本」，使用已开通的邮箱和密码登录。第一次使用该账号需要联网读取云端账本。退出后回到本地模式，之前的本地账本独立保留。再次登录同一账号会继续尝试提交该账号在此浏览器保存的修改。

离线时可在已读取过的云端账本中继续记账。待同步修改会在重新联网、刷新或重新打开页面后尝试提交。页面在后台时可能被手机系统暂停，同步会在重新打开时继续。清理站点数据、卸载应用或换浏览器前，应先确认同步完成，或导出本机待同步账本。

发生冲突时自动暂停提交。在状态按钮中可查看云端最新账本、导出本机待同步账本。两份记录都保留。恢复备份须在当前窗口已同步且联网时确认，恢复前安全副本存于该账号的本机缓存。恢复请求仍需通过云端版本校验。

## 实现与边界

- Service Worker `shuangbiao-v9` 仅预缓存应用壳、脚本、清单和图标。云端 API 请求绕过 Service Worker 的缓存和浏览器 HTTP 缓存。页面向当前控制它的 Worker 确认缓存策略后，才会访问 Supabase。
- 原账本键继续由本地模式管理。云端账本、选中行程和恢复前安全副本按 Supabase 用户 ID 保存。浏览器站点存储仍需要设备本身的访问保护。浏览器须支持 Web Locks，同一账号在同一浏览器只有一个窗口写入，其余窗口读取缓存。
- 一次本地写入保存账本、未提交标记和提交中请求。网络失败时以原 commitId、基准版本和请求正文重试。提交中的新修改单独保存在最新快照，前次得到确认后再生成下一次提交。整账本共享一个云端版本，各设备改动不同行程也可能发生冲突。
- 退出时立即清除本机登录会话。在线时也尝试退出当前的 Supabase 会话，不影响其他设备。待同步账本仍留在该浏览器内，等待相同账号再次登录。

## 测试与 M6

运行 `node tests/cloud-sync.cjs` 以在临时 Edge 配置、随机本地端口和模拟 API 上检查断网、刷新、重启、重放、冲突、旧备份和窄屏。可用 `node tests/cloud-sync.cjs --real-api` 对专用项目执行少量真实 API 验证，进程环境提供 `LEDGER_M5_PROJECT_REF` 和 `LEDGER_M5_SECRET_KEY`。管理密钥仅用于本次自动化脚本创建和清理临时账号，浏览器使用公开密钥及普通用户会话。

M6 先用 iPhone 主屏幕 PWA 和测试账号验证更新接管、离线打开、重启及联网恢复。真机通过后，先导出原本地完整备份，再由用户明确确认真实目标账号和首次迁移。首次迁移应核对目标云端版本、行程与业务记录 ID、数量、库存、收款和成本，同时保留原本地账本与备份。
